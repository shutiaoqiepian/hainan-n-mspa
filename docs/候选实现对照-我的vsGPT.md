## GPT 的版本为什么整体下沉

主要来自 `fAodCandidate = exp(−aod/0.7)`。它和现有分档完全是两套标度：

| AOD | 现网 fAod | GPT fAod | 结果因子 aodF |
|---|---|---|---|
| 0.05 | 1.00 | 0.931 | 1.000 → **0.969** |
| 0.10 | 1.00 | 0.867 | 1.000 → **0.940** |
| 0.20 | 0.97 | 0.751 | 0.987 → **0.888** |
| 0.30 | 0.92 | 0.651 | 0.964 → **0.843** |
| 0.50 | 0.80 | 0.490 | 0.910 → 0.770 |

**连"AOD 0.1 的干净天"都从 1.00 掉到 0.867。** 这个因子是乘进去的，
再经过 1.8 次方放大，等于给全站分数打了个 0.83 的折。

它的 `fWetCandidate` 也不是在替换阈值，而是换了一个形状：
`pop=40,rh=80` 时给 0.764（现网 0.62，更宽松），
`pop=55,rh=85` 时给 0.441（现网 0.62，更严格）——曲面本身变了。

### 实测影响（今天 169 个机位）

```
平均分：20.2 → 16.6
等级变化：30 / 169
  中烧→小烧 16 个
  小烧→微烧  4 个
  大烧→中烧  3 个
  火烧云→中烧 3 个   ← 掉两档
  微烧→不烧  3 个
```

自测用例：教科书级大烧 86 → **77**（大烧→中烧），云量最佳窗口 80 → **68**（中烧→小烧）。

**用户会立刻发现"网站变严格了"**，而这没有任何数据支撑。

## 我的版本怎么做的

同样是单调插值（PCHIP，不会过冲），但多了一步 **均值校准**：

- 每条曲线乘一个系数（`K_AOD=1.0013`、`K_POP=0.9968`、`K_RH=0.9770`），
  让新曲线在一批参考输入上的平均值与原阶梯一致；
- 系数在模块加载时从固定网格算出，不依赖外部数据，可复现；
- AOD 在 0.8 处额外压一个 0.30 节点——**重霾不能被平滑成"中等透明度"**，
  那是摄影上最要命的区别（GPT 版没有这个约束，0.85 给 0.32，接近两倍宽松）。

结果：跳变 25 → 1 分，而 169 个机位平均只动 −0.44 分，排序相关 0.9998。

## GPT 那份东西里**确实更好**的部分

### 1. `finiteInRange`：拦住 NaN —— 这个我照收了

它指出要用 `Number.isFinite` 而不是 `!= null`。查了一下，**现网确实有这个洞**：

```
typeof NaN === 'number'  → true
```

所以只要 API 返回一个 `NaN`，它会一路穿到 `scoreOf`，页面显示 **"NaN"**。
（`Infinity` 同理。）

已修（提交里包含）：

| 位置 | 改动 |
|---|---|
| `api.ts` `fieldOf` / `profField` / AOD 读取 | `typeof v === 'number'` → `Number.isFinite(v)` |
| `clouds.ts` `num()` | 同上 |
| `scoring.ts` `scoreOf` | 新增 `num()` 过滤 null/NaN/±Infinity/超范围；末尾再兜一次非有限值 |
| `api.ts` 新增 `validNumber(v, min, max)` | 范围校验，供 `qualityOf` 用 |

### 2. 它的 `dataCompleteness` 思路和我已上线的 `qualityOf` 一致

差别只是：它返回 0–1 的比例，我返回 `{ completeness: 0–100, missing[], status }`。
我保留了后者的形状（界面需要字段名和分级），但把它的**校验逻辑**合了进去。

### 3. "先加候选入口、新旧并列输出"——和我做的一样

它建议在 `api.ts` 里同时输出 `oldScore / candidateScore / scoreDelta / missingFields`。
这一版我先用**离线对照脚本**实现（`tools/compare-candidates.mjs`），
没有往页面塞第二列分数——因为还没确定要不要换。

## 建议

1. **采纳 GPT 的 `finiteInRange` 思路**（已做，这是真 bug）；
2. **不采纳它的 AOD/湿度常数**——那会把全站分数压低一档，且没有依据；
3. 如果喜欢它的曲线形状，**必须先在分数尺度上把均值校准回 20.2 → 20.2**，否则等于换了个量纲；
4. 我的候选也**先别上线**，等 30 天 METAR 数据出来看"无云却给高分"的比例再定。
