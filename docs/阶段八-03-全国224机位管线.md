## 1. 管线设计（复用，不重写）

`tools/xsec/build_cross_national.py` 与 `build_cross.py` 共用同一套
下载 / 解码 / 插值 / 量化函数（`import build_cross as bc`），只在三处不同：

| 项 | 试点（海南 8 机位） | 全国 224 机位 |
|---|---|---|
| 机位来源 | 手写 8 个 | `src/data/forecast/spots.json` 全部 224 个 |
| 方位 | 5 个（240/255/265/280/295）可选 | **当天日落方位 1 个**（每机位不同） |
| 分组下载 | 单窗口 | **纬度带 3° × 经度带 4°**，同带共用一次 GRIB 取数 |
| 采样 | 0–320 km 共 9 点 | 相同（同一套几何，保证可比） |
| 输出 | `data/cross/hn-*.json` + `index.json` | `data/cross/<prov>/<id>.json` + `national-index.json` |

**为什么按 3°×4° 分带而不是 1° tile**：实测 224 个机位按 1° tile 会被切成 124 组
（大量 1–2 机位的碎组，每个都要单独下载一次），按 3°×4° 只切 53 组
（最大组 37 个机位、18 个单机位组），下载次数 124×3 → 53×3。

**时次**：沿用 `pick_cycle_and_hours`（日落前 2h 到日落后 1h 的 4 个整点）。

## 3. 质量报告（`tools/xsec/quality_national.py`）

```
全国机位：224 个，合格 224，不合格 0
总字节 4.04 MB，单机位平均 18.4 KB
缺测比例：中位 0.000，最大 0.000
有降水采样点的机位：224 / 224；最大降水率 4.43 mm/h
有云机位：184 / 224
```

检查做了什么（不是"跑完就算数"）：

1. **覆盖**：按 `spots.json` 逐个点名核对，缺一个就报「无文件」；
2. **结构**：`levelFields` 11 项、采样距离 9 个点、时次与方位数；
3. **数据真实性**：缺测比例（>50% 判不合格）、地形遮罩（`belowGround=1` 但高度明显高于地形）、
   降水率与云水量级；
4. **分布**：逐省合格/不合格统计。

**220 个机位没有云**是正常现象（那一刻全国大部分地方天上没云），不是缺数据。

## 4. 踩到的两个坑（都已修）

1. **GRIB 缓存键没带裁剪窗口**：`filter_<cycle>_f<fh>.grib2` 只按起报+时效命名，
   全国批量给不同 tile 用不同 `DOMAIN` 时会**把海南窗口的文件当成别处的缓存**用，
   于是 `PRATE 网格与气压层不一致，丢弃`。修法：缓存文件名加入窗口
   （`..._17_21_107_112.5.grib2`），并清掉旧缓存。
2. **`pick_cycle_and_hours` 返回的日期是 `'YYYYMMDD'` 字符串**，不是 `date` 对象：
   第一版 `sunset_az()` 里调 `d.date()` 直接 `'str' object has no attribute 'date'`，
   每个机位都失败。修法：兼容 `'YYYYMMDD'` / `'YYYY-MM-DD'` / `date` 三种输入。

## 6. 已知限制（写在前面，别让后来的自己误会）

1. **全国机位只有 1 个方位**（当天日落方位），不能像试点那样在 5 个方位间对比；
2. **全国机位没有 `context.json`**（DEM 剖面 / AOD），所以「地形来源」显示为模式地形、
   AOD 显示缺测——这是真实状态，不是 bug；
3. 全国机位只在**日落方位**采样，若用户想拍其它方向，需要重新生成（可加 `--spots` 单跑）；
4. 数据每天会被覆盖（与试点一致），历史版本不留存；验证数据靠 `data/obs/xsec-snapshot/`；
5. 体积 4 MB 进仓库，每次更新都会产生 diff——如果日后变成每天多次，需要改成对象存储或分批。
