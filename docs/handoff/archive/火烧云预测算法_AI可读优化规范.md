# 火烧云风光摄影预测算法优化规范

## 0. 给后续 AI 的执行说明

你是一名结合大气物理、数值天气预报、遥感、统计学习与风光摄影的研究助理。请严格依据本文及用户提供的现有算法开展工作。

### 必须遵守

1.  **先审查，再修改。**
    不要在没有解释原因的情况下直接重写公式或改变现有输出。
2.  **区分证据等级。**
    明确标注哪些内容来自现有源码、哪些来自外部文献、哪些是物理推断、哪些只是待验证的工程假设。
3.  **不得虚构准确率。**
    没有真实观测标签和独立测试集时，不得声称准确率、命中率或概率已提高。
4.  **保留基线版本。** 现有算法必须保留为 baseline，所有改进都应能与
    baseline 对照。
5.  **不得数据泄漏。**
    训练时只能使用预测时点实际可获取的信息；事后卫星观测、再分析数据不能冒充当时的预报输入。
6.  **概率与评分分开。** 0--100
    评分不是事件发生概率。只有经过独立历史样本校准后，才可称为概率。
7.  **针对摄影决策优化。**
    重点关注"最值得出门的时段能否排在前面"、误报、漏报和机位可拍性，不只追求单一统计指标。
8.  如资料不足，列出缺失信息、所需数据和可验证实验，不得用臆测填补。

### 建议交付顺序

1.  解释现有算法与数据流。
2.  找出高风险假设及代码实现问题。
3.  提出可验证的改进方案。
4.  设计历史数据集和标签标准。
5.  给出可运行代码与单元测试。
6.  提供基线对比、验证指标和限制说明。

## 1. 项目目标与边界

### 1.1 目标

预测某地点某一日出或日落时段出现适合风光摄影的火烧云的机会，并对不同拍摄时段和机位进行排序，帮助摄影者决定是否前往拍摄。

### 1.2 不是目标

-   不把启发式评分包装成官方天气预报。
-   不把单个分数直接解释为真实发生概率。
-   不保证每一次高分都出现火烧云。
-   不用事后数据伪装成提前预报数据。
-   不假定一套固定阈值适用于所有纬度、季节、海岸与内陆场景。

### 1.3 建议输出

每个地点、日期和日出/日落时段至少输出：

-   `environment_score`：环境适宜度评分，0--100。
-   `event_probability`：火烧云事件概率；未校准时为 `null`。
-   `photo_opportunity`：指定机位的拍摄机会评分或概率，需与事件概率分开。
-   `forecast_lead_hours`：预报提前量。
-   `data_completeness`：输入数据完整度。
-   `uncertainty`：不确定性等级或区间。
-   `main_positive_factors`：主要有利因素。
-   `main_risks`：主要风险。
-   `recommended_window`：建议关注的时间窗口。
-   `model_version`、`input_sources`、`issued_at`：模型版本、数据来源和发布时间。

## 2. 现有算法基线概述

现有 JavaScript 文件包含以下主要模块：

1.  `fHigh(high)`：根据高云量计算高云因子。
2.  `fLow(low)`：低云越少，得分越高。
3.  `fMid(mid)`：中云量超过指定阈值后逐步扣分。
4.  `fAod(aod)`：按 550 nm 气溶胶光学厚度分档。
5.  `fWet(pop, rh)`：根据降水概率和近地面相对湿度计算湿润惩罚。
6.  `scoreOf(m)`：将因子相乘、整体进行 1.8 次幂变换，得到 0--96
    的启发式分数。
7.  `sunPosition(...)`：计算太阳高度角和方位角。
8.  `faceMatch(face, az)`：根据机位朝向和太阳方位进行修正。
9.  `profileMod(...)`：根据 850、700、500、400 hPa
    相对湿度及边界层高度进行经验修正。
10. `finalScore(...)`：合并逐时平滑、多模式分歧、机位朝向、高空湿度剖面和次日折扣。

现有文件明确说明：阈值未经历史回测；分数主要用于相对排序，不应直接作为火烧云的绝对发生概率。

### 2.1 当前重要经验参数

  模块         当前设定                                    当前性质
  ------------ ------------------------------------------- ------------------------
  高云         8%、55%、78% 等阈值                         启发式假设
  低云         82% 时因子降至 0                            启发式假设
  中云         55% 以内不扣分，95% 附近降至 0              启发式假设
  AOD          0.1、0.2、0.3、0.5、0.8 分档                经验分档
  降水概率     40%、70% 分界                               经验分档
  近地面湿度   88%、93% 分界                               经验分档
  整体指数     1.8 次幂，分数封顶 96                       未经回测的映射
  多模式分歧   标准差折扣，最高扣 28%                      未经概率校准
  机位朝向     方位差、110° 截止尺度、0.55 下限            简化几何近似
  湿度剖面     固定修正系数 0.72、0.82、1.10、0.95、0.90   经验规则

## 3. 主要科学与工程风险

### 3.1 云量不等于云的透光能力

高云量不能单独代表优质火烧云。相同云量可能对应不同云型、云厚、云光学厚度、云相态、云顶高度与空间分布。

**建议：** -
有数据时加入云光学厚度、云顶高度、云相态、云底高度等特征。 -
无直接云光学特征时，将云量作为代理变量，并标记其局限。 -
通过历史观测拟合云量与目标事件的非线性关系，不预先规定所有地点都存在同一个最佳高云量区间。

### 3.2 机位朝向不能直接等同于火烧云发生概率

太阳方位与机位朝向的差值，只能描述一部分几何关系。云所在天空方位、太阳高度、拍摄视场、地形遮挡和云层受光情况同样重要。

**建议：** - 分开计算 `event_probability` 与 `photo_opportunity`。 -
若只有粗略机位朝向，应把结果标为近似可见性评分。 -
具备云图或天空分区观测时，进一步估计目标方向上的受光云覆盖。

### 3.3 相对湿度不等于实际云量

高空相对湿度可用于描述云形成环境，但不能直接替代实际云覆盖、光学厚度和云相态。固定地对高层湿度加分可能在没有足够云的情况下虚增分数。

**建议：** - 优先使用实际云产品和云层特征。 - 将湿度剖面作为辅助变量。 -
通过消融实验验证湿度剖面是否提供独立预测价值；若无稳定增益，应移除或降低其权重。

### 3.4 AOD 不是完整的大气通透度指标

AOD
描述指定波长下整层大气气溶胶的光学消光，但并不完整描述粒径分布、吸收特性、单次散射反照率、相函数、垂直分布及水汽影响。

**建议：** - 保留连续 AOD 值，避免未经验证的分段跳变。 -
标明波长、数据来源、空间分辨率、预报时间和时间戳。 -
在数据可用时加入能见度、气溶胶组分等特征。 - 不把"低 AOD
必然更好"当成无条件规律；需按目标事件和地区回测。

### 3.5 降水概率和近地面湿度阈值未经验证

固定分界容易造成阈值附近分数突跳，也可能将"降水概率"误当作实际降水强度或云层遮挡程度。

**建议：** - 保留原始连续值。 -
可尝试逻辑回归、样条函数或树模型学习非线性关系。 -
比较固定阈值与连续特征的独立测试表现。

### 3.6 多模式分歧不等于固定比例的风险

多个模式的分数标准差只是一个不确定性代理量。模式可能共享初始条件、参数化方案或系统性误差，不能简单认为每个模式都提供独立证据。

**建议：** - 按预报提前量和天气情形统计分歧与真实误差的关系。 -
将各模式原始特征、模式身份、模式偏差和分歧统计纳入校准。 -
不在未回测时固定"标准差达到某值就扣固定百分比"。

### 3.7 缺失值固定填补可能制造虚假的确定性

把缺失云量或湿度统一替换成不利值会产生系统性低估，也无法表达数据质量差异。

**建议：** - 区分"观测为零"和"没有数据"。 - 记录每个特征的缺失标志。 -
比较多种缺失值处理方法，并在验证集上评估。 -
输出数据完整度；关键变量缺失时扩大不确定性或拒绝输出概率。

### 3.8 固定次日折扣与固定时序平滑未经验证

所有次日预报统一扣分，无法体现不同模式和提前量的真实预报技巧。时间平滑也可能抹掉短暂但重要的火烧云窗口。

**建议：** - 按预报提前量校准，不直接使用固定 0.95 折扣。 -
保留原始逐时分数；平滑结果只作为可选展示曲线。 -
不要让平滑跨越日出、日落或明显天气过程边界而制造虚假的峰值。

## 4. 建议的新模型架构

采用"物理启发式基线 + 多源数据特征 + 统计模型 + 概率校准"的架构。

### 模块 A：环境适宜度

输入： - 高、中、低云量、总云量。 -
云光学厚度、云顶高度、云相态、云底高度（可用时）。 -
AOD、气溶胶组分、能见度。 - 降水量、对流降水或相关对流指标。 -
多层相对湿度、边界层高度。 - 太阳高度角、方位角、距日出或日落的时间。

输出：`environment_score`，0--100。该值是评分，不自动代表概率。

### 模块 B：预报可信度

输入： - 预报提前量。 - 模式身份。 - 模式之间的差异。 -
各模式历史偏差。 - 数据缺失率和观测质量。

输出：不确定性指标、数据完整度和可信度等级。

### 模块 C：机位拍摄机会

输入： - 环境预测结果。 - 机位经纬度、机位朝向、视场角。 - 太阳位置。 -
目标天空方向上的云分布。 - 地形或地平线遮挡（可用时）。

输出：`photo_opportunity`。不要把这一结果直接乘回事件概率，除非这种组合方式经过验证。

### 模块 D：可训练预测模型

至少比较以下模型： 1. 原有规则算法（baseline）。 2.
逻辑回归（可解释基线）。 3. 随机森林。 4. LightGBM 或其他梯度提升树。 5.
如样本量和观测条件足够，再考虑时序模型或更复杂的模型。

不要因为某个模型在单次随机拆分中得分更高，就直接判定其泛化能力更好。

### 模块 E：概率校准

模型必须先输出可验证的预测概率，再通过独立验证数据进行校准。可比较： -
Logistic / Platt calibration。 - Isotonic regression。 -
其他适合样本量与类别分布的校准方法。

校准后仍需在独立测试集上检查可靠性。若数据量不足，`event_probability`
应为 `null`，或明确标注为未校准的模型估计值。

## 5. 数据集与标签规范

### 5.1 推荐数据范围

先以海南地区为试验区域，覆盖不同季节、日出与日落、沿海与内陆、不同预报提前量。首轮可收集
6--12
个月样本，但样本量应由事件频率和统计检验需求决定；这不是保证足够训练的固定标准。

### 5.2 每条记录的最小字段

  字段                       说明
  -------------------------- ------------------------
  `site_id`                  机位标识
  `latitude`, `longitude`    坐标
  `event_date`               事件日期
  `event_type`               sunrise / sunset
  `forecast_issued_at`       预报发布时间
  `valid_time`               预报有效时刻
  `forecast_lead_hours`      提前量
  `model_name`               数据模式
  `features`                 预测时实际可用的特征
  `observation_source`       观测来源
  `label_flaming_cloud`      是否达到火烧云事件标准
  `label_intensity`          强度等级
  `label_duration_minutes`   持续时间
  `label_photo_quality`      摄影成片质量评分
  `label_confidence`         标签可信度
  `data_version`             数据版本

### 5.3 标签标准必须提前制定

火烧云标签容易受到曝光、白平衡、后期处理、拍摄方向和个人审美影响。建议在建模前制定一致的标注规程：

-   统一火烧云定义和强度分级。
-   尽量使用原始文件或记录拍摄参数。
-   保存拍摄时间、方向和机位。
-   让至少两位标注者独立评分，并记录分歧。
-   将"天空出现红色云彩"和"照片具有高摄影价值"分开标注。
-   记录无火烧云的时段，避免只收集成功照片造成严重选择偏差。

### 5.4 防止数据泄漏

-   同一天相邻时间的样本不能随意分到训练集和测试集两侧。
-   优先按日期或连续时间段划分训练、验证和测试集。
-   另外进行按机位或地区留出的泛化测试。
-   使用当时真实可获得的预报快照，而不是事后更新的预报。
-   ERA5
    等再分析数据可用于解释天气背景或辅助研究，但不能在未经说明时替代历史预报输入。

## 6. 回测与评价方法

必须与原始 baseline 进行同一数据集、同一标签、同一拆分条件下的比较。

### 6.1 分类和概率指标

-   **Brier Score：** 衡量概率预测的平方误差。
-   **Brier Skill Score：** 衡量相对于基线概率预测的技巧。
-   **ROC-AUC：** 衡量排序区分能力。
-   **PR-AUC：** 在火烧云样本较少时评估精确率与召回率的权衡。
-   **Reliability diagram：** 检查预测概率与实际发生频率是否一致。
-   **Calibration error：** 辅助评价概率校准，但应明确具体计算方式。

### 6.2 摄影决策指标

-   Top-3 / Top-5
    命中率：每周或每个计划窗口选出的前几个时段，实际命中多少。
-   误报率：高分但没有目标事件的比例。
-   漏报率：低分却实际出现目标事件的比例。
-   提前量分层表现：例如 0--6、6--24、24--48 小时分别统计。
-   机位分层表现：沿海、内陆、不同朝向分别统计。
-   决策成本：考虑交通时间、距离和错过拍摄窗口的代价。

### 6.3 必须使用简单基线

至少比较： - 历史发生率基线。 - 只用总云量与太阳几何的简单模型。 -
当前启发式算法。 - 新的统计或机器学习模型。

如果复杂模型不能在独立测试集上稳定优于简单基线，不应上线为默认模型。

## 8. 推荐实施路线

### 第 1 步：冻结 baseline

保存原始代码、参数、测试样例和版本号。任何修改都要能与原始版本对照。

### 第 2 步：修复结构问题

-   拆分环境评分和机位拍摄机会。
-   将数据缺失与不利天气区分。
-   把预报提前量作为显式特征。
-   保留原始逐时曲线，平滑仅用于展示。
-   对太阳位置函数做独立单元测试，并与可靠的天文算法或 NOAA 结果核对。

### 第 3 步：建立数据与标签

统一机位、时间、预报版本、观测照片、事件标签和拍摄质量标签。记录数据来源和质量。

### 第 4 步：完成回测

用时间外测试比较 baseline、逻辑回归、随机森林和
LightGBM。报告置信区间、各季节表现、不同提前量表现和样本量。

### 第 5 步：校准概率

只有在样本足够且独立测试表现稳定时，才发布概率。否则继续使用评分和定性等级。

### 第 6 步：部署和持续监测

每次预测保存输入快照、输出结果和模型版本。新季节或模式升级后重新评估，检查模型是否出现性能漂移。

## 9. 对 AI 的最终任务要求

当用户要求你优化算法时，按以下顺序执行：

1.  阅读原始算法源文件，不要只看本文摘要。
2.  给出逐项代码审查结果，区分代码错误、物理假设风险和未经验证的阈值。
3.  提出最小改动方案和完整升级方案，说明各自成本、收益与风险。
4.  先实现可测试的基线改进，不得伪造训练数据或测试结果。
5.  所有公式和阈值应说明来源；没有可靠来源的标为"待回测假设"。
6.  提供完整代码、输入输出契约、缺失值策略、单元测试和复现实验步骤。
7.  设计历史回测流程，说明数据拆分、数据泄漏防范、指标和置信区间。
8.  在没有实测证据时，只能说"理论上合理"或"待验证"，不能说"准确率已提升"。
9.  文献结论必须与原文研究范围相匹配；不确定的书目信息必须标注待核实，不能编造
    DOI、数据或实验结果。
10. 最终交付应使另一位开发者能够复现算法、检查假设并独立验证结果。

## 10. 核心结论

本项目的主要瓶颈不是缺少更多经验系数，而是缺少与真实火烧云观测相匹配的标签、历史预报快照和严格的独立回测。

优先方向是：

1.  提高云层结构和光学特征的表达能力。
2.  区分事件概率与机位出片机会。
3.  将模式分歧和提前量通过历史数据校准。
4.  用统一标签构建海南本地样本集。
5.  通过时间外测试验证任何修改是否真正有用。

**没有历史回测，任何"优化后准确率提高"的说法都不成立。**
