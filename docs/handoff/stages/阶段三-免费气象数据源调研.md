## 0. 先说结论（三张图说完）

### 0.1 「三维云水/云冰」谁能给 —— 这是整个剖面系统的分水岭

任务书 3.4 把「云液态水混合比、云冰混合比」列为**第一优先级**，并明确要求
「不允许将不同物理量混为一谈」。实测下来：

| 数据源 | 三维云水 | 三维云冰 | 三维云量 | 能否做真正的剖面 |
|---|---|---|---|---|
| Open-Meteo API | ❌ 没有 | ❌ 没有 | ⚠️ 有，但**是 RH 诊断值**（已实测） | 只能算「估算」 |
| **NOAA GFS pgrb2.0p25** | ✅ **CLWMR** | ✅ **ICMR** | ❌ 无分数（有低/中/高） | ✅ **可以** |
| ECMWF Open Data | ❌ 只有整层积分 | ❌ 只有整层积分 | ❌ 只有低/中/高三层 | ❌ 不行 |
| CAMS | 🅾️ 有气溶胶垂直分布 | — | — | 只补气溶胶 |
| ERA5 | ✅ CLWC | ✅ CIWC | ✅ CC | 只能做历史验证 |

> **结论：能同时给出「云水 + 云冰 + 分开标记」的免费实时源，目前只有 NOAA GFS。**
> 这不是偏好问题，是唯一选项问题。

### 0.2 现在我们线上用的数据的真实身份（实测确认）

这条很重要，因为它决定界面上必须写什么话：

| 我们用的字段 | 它的真实身份 | 证据 |
|---|---|---|
| `cloud_cover_low/mid/high` | **模式原生的三层云量** | 与压力层云量按最大重叠重建的吻合率只有 29.6% / 90.8% / 59.2%，`low` 层差 15 个百分点 → 不是同一套口径 |
| `cloud_cover_{L}hPa` | **由相对湿度算出的诊断值** | RH<40% 的 897 个样本云量**恒为 0**；RH≥100% 时均值 91%；ECMWF/GFS/ICON 三个模式在 RH=80% 处分别只有 4%/1%/4% → 共享同一套 RH 诊断公式，不是各模式自己的云方案 |

**这意味着两件事：**

1. 现有评分用的是**模式原生三层云量**，这一点是对的、不用改。
2. 但「云层剖面图」里那 8 层用的是 `cloud_cover_{L}hPa`，**本质是湿度换算出来的**。
   界面上必须标「估算」，不能画得像卫星实测云图。任务书 3.5 的第三优先级要求兑现。

### 0.3 一条硬约束（决定了架构）

静态站（Cloudflare Pages）**不能**在用户点开剖面时才去下 GRIB。
508 MB/时刻的文件、GRIB2 解析、Python 运行时，浏览器里一样都没有。

→ 剖面数据必须**在 GitHub Action 里预计算**，写成 JSON 提交进仓库，
   前端只读 JSON 画图。这与现在 `data/forecast/*.json` 的做法一致。

## 1. Open-Meteo（实测）

- 官方文档：https://open-meteo.com/en/docs
- ECMWF 子集：https://open-meteo.com/en/docs/ecmwf-api
- 许可：免费档限**非商业用途**；商业需付费。数据本身来自各国家气象机构＋ECMWF CC-BY-4.0

### 1.1 压力层变量（17 层：1000/950/925/900/850/800/700/600/500/400/300/250/200/150/100/70/50 hPa）

**有（全部 17 层实测可用）：**

| 变量 | 参数名 | 单位 | 850hPa 实测值 |
|---|---|---|---|
| 云量 | `cloud_cover_{L}hPa` | % | 11 |
| 相对湿度 | `relative_humidity_{L}hPa` | % | 82 |
| 温度 | `temperature_{L}hPa` | °C | 18.6 |
| 露点 | `dew_point_{L}hPa` | °C | 15.5 |
| 位势高度 | `geopotential_height_{L}hPa` | m | 1539 |
| 风速 | `wind_speed_{L}hPa` | km/h | 6.7 |
| 风向 | `wind_direction_{L}hPa` | ° | 118 |
| 垂直速度 | `vertical_velocity_{L}hPa` | m/s | 0 |

**没有（返回 `Invalid value`）：**

- ❌ `cloud_liquid_water_{L}hPa`（云水混合比）
- ❌ `cloud_ice_{L}hPa`（云冰混合比）
- ❌ `cloud_water_content_{L}hPa`
- ❌ `specific_humidity_{L}hPa`（比湿）
- ❌ `potential_temperature_{L}hPa`（位温）
- ❌ `u_component_of_wind_{L}hPa` / `v_component_of_wind_{L}hPa`（只有速/向，没有分量）

> 风速/风向可以自己拆成 u/v：`u = -speed·sin(dir)`、`v = -speed·cos(dir)`，
> 但这是**从标量反推**，会丢掉矢量平均的信息。做风场流线够用，做定量散度不够。

### 1.2 地面/单层（实测）

有：`cloud_cover`、`cloud_cover_low/mid/high`、`total_column_integrated_water_vapour`、
`cape`、`convective_inhibition`、`boundary_layer_height`、`visibility`、
`shortwave_radiation`、`direct_normal_irradiance`、`direct_radiation`、`diffuse_radiation`、
`precipitation`、`precipitation_probability`、`temperature_2m`、`dew_point_2m`、
`relative_humidity_2m`、`wind_speed_10m`、`wind_direction_10m`、`surface_pressure`、
`freezing_level_height`

半可用：`cloud_base`、`cloud_top` —— **参数名合法但返回全是 null**（海南实测两天全部 null）。
→ 不能拿它当云底/云顶用，界面上也不能显示这个数。

没有：`sea_level_pressure`、`zero_degree_level`

### 1.3 气溶胶（Air Quality API，底层是 CAMS）

有：`aerosol_optical_depth`（无量纲，0.16）、`pm2_5`、`pm10`、`dust`、`uv_index`、
`carbon_monoxide`、`nitrogen_dioxide`、`ozone`、`sulphur_dioxide`、`ammonia`
（`ammonia` 参数存在但值常为 null）

没有：任何**组分 AOD**（海盐/有机物/黑碳/沙尘/硫酸盐 AOD）、`aerosol_optical_depth_550nm`

→ 想要「霾的成分」必须去 CAMS 本体（需注册，见 §4），Open-Meteo 只给总量。

### 1.4 请求限制与更新

- 免费档约 10 000 次/天、600 次/分钟；**一次请求多个坐标按坐标数计费**
  （本项目实测 224 机位逐省跑会撞 429，已改为每批 8 坐标 + 1.5 s 间隔）
- 更新频率随所选模式；ECMWF 约 4 次/天

## 2. NOAA GFS / NOMADS（实测，**本项目的主数据源**）

- 入口：https://www.nco.ncep.noaa.gov/pmb/products/gfs/nomads/
- 数据目录：https://nomads.ncep.noaa.gov/pub/data/nccf/com/gfs/prod/
- 许可：美国政府作品，公有领域（public domain），无注册、无 key

### 2.1 文件命名

```
https://nomads.ncep.noaa.gov/pub/data/nccf/com/gfs/prod/
  gfs.YYYYMMDD/HH/atmos/
    gfs.tHHz.pgrb2.0p25.fFFF          ← GRIB2 全量（本例 508.5 MB）
    gfs.tHHz.pgrb2.0p25.fFFF.idx      ← 旁挂索引，743 行
```

### 2.2 索引格式（这一行就是「按需下载」的钥匙）

```
471:344036294:d=2026103112:CLWMR:850 mb:3 hour fcst:
 │      │                    │     │
 │      │                    │     └─ 层级
 │      │                    └─ 变量短名
 │      └─ 该消息在文件中的**起始字节**
 └─ 第几条消息
```

### 2.3 实测：云水/云冰到底有没有

```
变量命中: {"CLWMR":23, "ICMR":23, "UGRD":58, "VGRD":58, "HGT":49,
           "TMP":57, "RH":51, "SPFH":44, "VVEL":42}
```

- **CLWMR**（cloud water mixing ratio）23 条 = 22 个气压层 + 1 个混合层
- **ICMR**（ice water mixing ratio）23 条
- 另外 `RWMR`（雨）、`SNMR`（雪）、`GRLE`（霰）也在，可用来区分「云」和「降水粒子」

气压层覆盖：1000, 975, 950, 925, 900, 850, 800, 750, 700, 650, 600, 550, 500,
450, 400, 350, 300, 250, 200, 150, 100, 50 mb（22 层）

### 2.4 实测：能不能只下需要的几层（决定可行性）

| 项目 | 实测结果 |
|---|---|
| `Range` 请求支持 | ✅ `206 Partial Content`，`accept-ranges: bytes` |
| CLWMR @ 850 hPa 单条大小 | **380 769 字节**（0.36 MB） |
| CLWMR @ 700 hPa | 0.16 MB |
| ICMR @ 850 hPa | 0.32 MB |
| 实下后检查 | 魔数 `GRIB`、edition 2、**声明长度 380 769 = 实收 380 769** ✅ |

**复现命令（照抄可跑）：**

```bash
# 1. 拿索引
curl -s https://nomads.ncep.noaa.gov/pub/data/nccf/com/gfs/prod/gfs.20261031/12/atmos/gfs.t12z.pgrb2.0p25.f003.idx | grep CLWMR

# 2. 只下 850hPa 那一层（用 awk 从上一条的偏移切到下一条）
#    实际实现里由脚本解析 .idx 算字节区间，再用 Range 取
curl -s -r 344036294-344417062 \
  https://nomads.ncep.noaa.gov/pub/data/nccf/com/gfs/prod/gfs.20261031/12/atmos/gfs.t12z.pgrb2.0p25.f003 \
  -o clwmr_850.grib2
```

### 2.5 成本估算（这是能不能落地的关键）

做一个剖面需要：沿路径 N 个点 × M 个气压层 × (云水+云冰)。

但注意：**下载的粒度是「整个变量-层」，不是「一个点」**。
GFS 0.25° 是 1440×721 全球格，一条 CLWMR@850 就是全球一张图。
所以「取 20 个点」和「取 2000 个点」下载量**一样**。

| 方案 | 每时刻下载 | 一场日落（18 小时 × 3 小时步长 ≈ 6 个时刻） |
|---|---|---|
| 8 层 × (CLWMR+ICMR) | ≈ 4 MB | ≈ 24 MB |
| 22 层全量云水云冰 | ≈ 12 MB | ≈ 72 MB |

GitHub Actions 跑这个完全没问题（runner 带宽足够，单次 20~70 MB）。
**这也是为什么必须放 CI：不能让访客下这个。**

### 2.6 缺点

- 只有 0.25°（≈28 km）分辨率，海南岛约 3~4 个格点 —— 剖面横向细节有限，必须如实标注
- 3 小时一个预报时刻（不是 1 小时）
- NOMADS 有访问频率限制（未公开具体值），需礼貌访问、加退避
- GRIB2 解析需要 eccodes/cfgrib（Python），Node 侧没有成熟等价物

## 3. ECMWF Open Data（官方文档核实）

- 官方页：https://www.ecmwf.int/en/forecasts/datasets/open-data
- 文件浏览：https://data.ecmwf.int/forecasts/
- **许可：CC-BY-4.0，允许再分发和商业使用，需署名** ✅ 这是最宽松的一个

### 3.1 有什么

- IFS：**0.25°**，以及 2026-10-20 起新增的 **0.1°**（0.1° 的 `-pl`/-sfc 分开发布，晚约 2 小时）
- AIFS（AI 模式）：仅 0.25°，`lcc/mcc/hcc/tcc` 只有地面场
- 4 次/天：00 / 06 / 12 / 18 UTC
- 步长：00/12z 为 0–144 每 3 小时；06/18z 为 0–144 每 3 小时
- 滚动归档：只保留最近 **12 次**预报（≈2~3 天）

### 3.2 气压层变量（层级 1000/925/850/700/600/500/400/300/250/200/150/100/50/10）

| 短名 | 含义 | 层类型 |
|---|---|---|
| `z` | 位势 | pl |
| `t` | 温度 | pl |
| `u` / `v` | 风分量 | pl |
| `q` | **比湿** | pl |
| `w` | **垂直速度** | pl |
| `vo` / `d` | 涡度 / 散度 | pl |
| `gh` | 位势高度 | pl |
| `r` | 相对湿度 | pl |

**✅ 有比湿和风分量 —— 这两样 Open-Meteo 没有。**

### 3.3 云（关键限制）

- 地面场：`tcc`（总云量）、`hcc`/`mcc`/`lcc`（高/中/低云量）
- 柱积分：`tciw`（Total column cloud ice water）、`tclw`（Total column cloud liquid water）
- **❌ 压力层上没有云水/云冰**，也没有三维云分数

→ 用 ECMWF 做剖面，云的垂直分布只能靠 `r`（相对湿度）推 → 又回到「估算」。
**这一条让 ECMWF 无法作为剖面主源，但非常适合做「独立模式对比」。**

### 3.4 注意别混淆

免费开放子集 ≠ 完整 ECMWF 产品。完整集（含三维云水、模式层）要商业许可。
文档里明确写了 open data 是 "a subset"。

## 5. ERA5（待实测，需注册）

- 官方：https://cds.climate.copernicus.eu/datasets/reanalysis-era5-pressure-levels
- CDS 账号 + API key，**未实测**

按公开资料，ERA5 气压层**有** `CLWC`（云液态水含量）、`CIWC`（云冰含量）、
`CC`（云分数）、`q`、`t`、`u/v/w`、`z` —— 是**唯一同时具备三维云水云冰和云分数的免费源**。

因为 METAR 只看得到云底和云量，看不到高层。

**建议：等 A 级样本攒够（≥30 天）再启动，现在接是浪费。**

## 7. 数据源组合建议

### 7.1 分层方案（按「能拿到什么」而不是「想要什么」定）

| 层 | 数据源 | 提供什么 | 谁在用 |
|---|---|---|---|
| L1 常规预报 | Open-Meteo | 三层云量、湿度、降水、AOD、太阳 | 现有评分（**不动**） |
| L2 剖面（云的三维结构） | **GFS pgrb2** | CLWMR/ICMR 22 层、温度、湿度、风、垂直速度 | 新剖面系统 |
| L3 模式对比 | ECMWF Open Data | 比湿、风分量、独立云量 | 剖面图上的「模式分歧」 |
| L4 气溶胶 | Open-Meteo（CAMS 代理） | AOD 总量 | 现有评分 |
| L5 历史验证 | ERA5 | CLWC/CIWC/CC | 以后验证用 |

### 7.2 明确不做的事

- ❌ 不把剖面系统的云量接进评分公式
  任务书第七部分和现有硬约束 1 都要求：`scoreOf` 不能动。
  剖面是**解释层**，不是**打分层**。
- ❌ 不接 CAMS 本体
  同源数据 Open-Meteo 已经在给，多接一套只增加维护成本。
- ❌ 不在浏览器端解析 GRIB
  静态站做不到，硬做会让首屏加载崩溃。

### 7.3 一个必须提的风险

GFS 只有 0.25°，海南岛横跨约 1.5°经度 → 剖面横向只有 3~6 个真实格点。
所谓「沿 265° 方向 0–50 km 的连续截面」里，**真实独立信息只有 1~2 个格点**，
其余都是插值。

任务书 3.2 明确说：「不要为了增加图表范围而制造不存在的空间细节」。
所以：
- 剖面长度默认 **0–50 km** 最合理（在 28 km 格距下还能反映一点梯度）
- 0–100 / 0–200 km 必须显著标注「横向分辨率 ≈28 km，细结构为插值」
- 图上要画出**真实格点位置**，让用户看见哪几处是实测格点、哪几处是插值
