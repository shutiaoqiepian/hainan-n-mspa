# 阶段八-05 · 剖面页「怎么看这张图」说明书

> 给摄影师的白话解释。目的只有一个：**让人知道每个按钮点下去会发生什么，以及什么时候该点它**，
> 而不是再加一堆气象术语。

## 一、为什么做这件事

`/cross` 那一排按钮（数据源 / 时刻 / 太阳时间 / 方位 / 视图 / 高度轴 / 高度 / 图层）对写代码的人是自解释的，
但对摄影师不是。原来的情况：

| 问题 | 表现 |
| --- | --- |
| 提示只靠 `title` | 桌面端要悬浮才出现；**手机端根本没有 title**，等于没解释 |
| 名词没有落地 | 「CLWMR」「TCDC」「Pa/s」是变量名，不是摄影语言 |
| 免责声明太长 | 图表下方那一大段是给审阅者看的，摄影师读不进去 |
| 不知道先点哪个 | 十来个按钮平铺，第一次来不知道顺序 |
| 误读风险 | 把「潜在云区」当云、把「降水」当降水概率、把「太阳时间」当分钟级预报 |

## 二、做了什么

新增一个**可折叠**面板，默认收起，位于机位选择之后、工具条之前：

```
[▸ 怎么看这张图 · 每个按钮是干嘛的          给摄影师的白话版 · 约 2 分钟读完]
```

点开后依次是：

1. **三十秒上手** —— 5 步操作顺序（选机位 → 对太阳方位 → 选日落整点 → 看云水视图 → 拖太阳时间滑杆）
2. **9 个工具条分组**，每组一句话总述 + 每个按钮三段式：
   - `它改变什么` —— 按钮到底动了哪个变量
   - `怎么用` —— 摄影师在什么情况下点它
   - `别误读` —— 这个按钮最容易产生的错误理解（可选，但关键项都有）
3. **图上那些东西是什么** —— 12 项图元图例：纵轴/横轴、云水云冰填色、真实格点虚线、模式层、
   模式地形、机位地面、太阳投影、夕阳照明边界、暖色受光、降水圆点

### 覆盖的按钮

| 分组 | 覆盖项 |
| --- | --- |
| 数据源 | GFS 模式云水、Open-Meteo 估算 |
| 时刻 | 4 个整点、日落时刻 |
| 太阳时间 | ±20 分钟滑杆 |
| 方位 | 240/255/265/280/295° |
| 视图 | 综合、云水、云冰、总云量 |
| 高度轴 | 海拔、离地 |
| 高度 | 0–8 / 0–16 / 0–22 km |
| 图层 | 湿度等值线、温度等值线、风矢量、垂直速度、潜在云区、降水 |
| 全屏 | 全屏 / 退出全屏 |

## 三、文案的硬性原则（改文案时不能破）

1. **不编造物理意义**。不确定就写「仅作参考」「看不出」，不硬解释。
2. **每个切云变量的按钮都必须说清边界**。例如「总云量」必须写明「是百分比，不是水量」。
3. **免责口径不能丢**（`tools/test-guide.mjs` 会拦）：
   - 降水是**降水率 mm/h，不是概率**；
   - 云场是**模式预报，不是雷达/卫星实测**；
   - 太阳时间是**只算光几何，不动云场**。
4. **不做营销腔**。写「别以它为准」比写「强大功能」有用。

## 四、实现位置

| 文件 | 作用 |
| --- | --- |
| `src/lib/xsec/guide.ts` | 纯文案数据：`TOOLBAR_GUIDE` / `CHART_GUIDE` / `QUICK_STEPS` |
| `src/pages/CrossSectionPage.vue` | 折叠面板模板 + `showGuide` 状态 |
| `src/styles/pages/cross.css` | `.xsec-guide-*` 样式（约 150 行） |

文案独立成文件的原因：这些解释要跟按钮一对一，散在模板里会变成几十个 `title`，改一个漏一个；
独立文件还能被静态测试逐条检查。

**没有碰的东西**：`scoreOf()`、`scoring.ts`、`data/forecast/` 一个字都没动——这只是解释层，不参与评分。

## 五、怎么验证

```bash
# 1) 文案完整性（不需要浏览器）：逐条字段齐全、分组对得上、免责红线没被冲掉
node tools/test-guide.mjs

# 2) 真实浏览器（无头 Edge + CDP）：默认收起 → 点击展开 → 统计分组/条目/字数 → 查横向溢出 → 截图
npm run build
npx vite preview --port 4173 --strictPort &
node tools/obs/verify-guide-ui.mjs
```

## 六、顺带做出来的东西

`tools/obs/miniwsc.mjs` —— 一个最小 WebSocket 客户端（约 180 行）。
本机 Node 20 没有全局 `WebSocket`，仓库也没装 `undici`/`ws`，而 CDP 需要 WebSocket。
自己实现的好处是不新增依赖；已支持 64 位长度帧（大截图必需）和分片重组。
以后要用无头浏览器做 UI 验证，直接复用它。

## 七、已知没做的

- **面板不记忆展开状态**：刷新后回到收起。想记的话可以存 localStorage。
- **没做锚点跳转**：9 个分组不能点击直达，只能滚动。内容量不大，暂时不值得加。
- **CI 没跑这些测试**：仓库 CI 只有 3 个数据缓存作业，没有单元测试环节。
  测试仍是本地手动跑（`tools/test-*.mjs` 一整套）。要接进 CI 需要新建 workflow，属于发布流程改动，没擅自动。
