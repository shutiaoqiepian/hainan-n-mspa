## 4. 完整数学表达（逐条复原）

### 4.1 五个因子

```
fHigh(h) = 0                                  h < 8
         = (h − 8) / 47                       8 ≤ h ≤ 55
         = 1                                  55 < h ≤ 78
         = 0.25 + 0.75(100 − h)/22            h > 78
                                    【scoring.ts:14-19】

fLow(l) = clamp(1 − l/82, 0, 1)      【scoring.ts:22-24】
fMid(m) = 1 (m ≤ 55); else clamp(1 − (m−55)/40, 0, 1)   【scoring.ts:27-30】

fAod(a) = AOD_BANDS 分档值            【scoring.ts:32-34, levels.ts:28-35】
          0.1→1.00  0.2→0.97  0.3→0.92  0.5→0.80  0.8→0.55  ∞→0.30

fWet(pop,rh) = p × r                  【scoring.ts:37-41】
          p = 1 (pop<40) | 0.62 (40≤pop<70) | 0.22 (pop≥70)
          r = 1 (rh≤88) | 0.78 (88<rh≤93) | 0.5 (rh>93)
```

### 4.2 主分数

设缺失填充 `ĥ = high ?? 90, m̂ = mid ?? 60, l̂ = low ?? 70, p̂ = pop ?? 60, r̂ = rh ?? 90`：

```
h    = clamp(fHigh(ĥ), 0, 1)
lowF = 0.30 + 0.70·fLow(l̂)
midF = 0.72 + 0.28·fMid(m̂)
aodF = 0.55 + 0.45·fAod(aod ?? 0.40)
wetF = 0.55 + 0.45·fWet(p̂, r̂)

raw   = h · lowF · midF · aodF · wetF
score = round( min(96, 100 · raw^1.8) )          【scoring.ts:46-70】
```

若 `h = 0` 直接返回 0（无高云 = 无画布）。

### 4.3 完整流水线（`api.ts compute`）

```
s1    = scoreOf(m[t])                          当前小时
sPrev = scoreOf(m[t−1])                        前一小时（t=0 时取 s1）
sNext = scoreOf(m[t+1])                        后一小时（末尾取 s1）

① 平滑   score = 0.25·sPrev + 0.50·s1 + 0.25·sNext        【api.ts:600】
② 分歧   spread = round(σ(各模式 score))                   【api.ts:589-591】
         score ×= 1 − min(0.28, spread/55)   仅多模式     【api.ts:604】
③ 朝向   score = round(score × face)                      【api.ts:608】
④ 剖面   score = clamp(round(score × prof.mod), 0, 100)   【api.ts:612】
⑤ 时效   score ×= 0.95（明天）                             【api.ts:615】
⑥ 封顶   score = clamp(score, 0, 96)                      【api.ts:616】
```

### 4.4 朝向与剖面

```
FACE_AZ = {西:270, 西南:235, 南:180, 东南:135, 东:90, 西北:305, 北:0}
d = 角距(太阳方位, 机位朝向)，取 [0,180]
faceMatch = 0.55 + 0.45·clamp(1 − d/110, 0, 1)     无朝向（山顶）时 0.9
                                              【sun.ts:41-55】

profileMod：ri = 各层相对湿度
  lowWet  = rh850 ≥ 80
  midWet  = rh700 ≥ 80
  highWet = rh500 ≥ 60 或 rh400 ≥ 60
  mod = 0.72(low&high) | 0.82(low) | 1.10(high) | 0.95(mid) | 0.90(其余)
  若 blh < 350 且 mod > 0.7 → mod ×= 0.94
                                              【scoring.ts:288-337】
```

### 4.5 专项指数

```
clarity（通透度）= 100·aodF·visF·cloudF·lowF                       【scoring.ts:82-96】
  aodF: ≤0.12→1, ≤0.2→.92, ≤0.3→.8, ≤0.5→.6, ≤0.8→.36, else .18
  visF: ≥25km→1, ≥15→.85, ≥8→.65, else .4
  cloudF: 总云≤20→1, ≤45→.88, ≤70→.68, else .45
  lowF = 1 − 0.35·(low/100)

crepuscular（云隙光）= 100·sunF·gapF·lowF·aodF·popF·visF·baseF·faceF × 0.85，上限 95
  edge(c) = 4c(1−c)  (c<0.08 → 0)，gap = max(edge(mid), edge(high), 0.75·edge(low))
  presence = clamp(max三层/30, 0, 1)，gapF = presence·(0.15+0.85·gap)
                                                    【scoring.ts:111-168】

pillar（太阳光柱）= 100·sunF·iceF·highF·lowF·aodF·popF·visF × 0.6，上限 88
  iceF 依据 500hPa ≤ −18℃、300hPa ≤ −35℃                          【scoring.ts:178-221】

rainbow（彩虹）= 太阳高度须 3°–42°，否则 0；100·sunF·rainF·convF·openF
  rainNear 由 rainbowHint 扫描 t−2…t 小时，要求 pop≥30% 或 CAPE≥1500，
  且该小时太阳高度在 4°–40°                              【scoring.ts:227-283】
```

### 4.6 云层剖面

```
有云判据：cover ≥ 30% 或 rh ≥ 80%                        【clouds.ts:205-206】
弱云：!byCloud && byHumid → coverEff = clamp((rh−60)·1.2, 15, 85) 【clouds.ts:208-211】
高度分档：≥6000 m 高云 / 2000–6000 m 中云 / <2000 m 低云    【clouds.ts:252-254】
云底：rawBase = height + 0.25·LCL（LCL<2500 时），夹在 [0, nextUp−50] 【clouds.ts:259-262】
云顶：min(nextUp, height + (900|600|400))                  【clouds.ts:263】
连片：相邻有云层高度差 > 2500 m 断开                        【clouds.ts:299】
```

### P1-1　阈值跳变【实测已确认】

实测（同一组输入，只挪阈值 ±0.1）：

| 阈值 | 越过前 → 后 | 跳变 |
|---|---|---|
| pop 40% | 86 → 61 | **−25** |
| pop 70% | 61 → 39 | −22 |
| rh 93% | 71 → 54 | −17 |
| rh 88% | 86 → 71 | −15 |
| AOD 0.5 | 74 → 59 | −15 |
| AOD 0.8 | 59 → 45 | −14 |

**为什么是 P1 不是 P2**：模式每次更新都可能让 pop 从 39→41，用户看到的分数就跳 25 分，
体感是"预报在乱变"，比"稍微不准"更伤信任。

修复成本：小（改成单调插值），但**会改分数水平**，必须留 baseline 开关。

### P1-2　事件概率与出片机会混算【源码已确认】

`api.ts:608` 把 `faceMatch` 直接乘进总分。后果：朝向差的机位分数被压，
与"天气本来不行"混在一起，无法单独回答"这个黄昏到底能不能烧"。

修复成本：中（拆两个字段 + UI 改版，需要保留旧字段做兼容）。

### P1-3　过期判定与失败处理糅在一起【源码已确认】

`api.ts:289`：`> 14 小时` 判定"缓存过期"→ 抛错 → `catch` 里直接 `loadLive()`。
若实时请求也失败，只剩 `state.error = '取不到数据'`。
用户无法知道：是数据旧了、还是自己断网了、还是 API 挂了。

修复成本：小（把 `state.error` 换成结构化 `qualityStatus`）。

### P1-4　评分用整点、详情用精确时刻【源码已确认】

`api.ts:573`（整点）与 `api.ts:578`（精确）算两次太阳位置，最多差 30 分钟。
影响：行内"太阳方位"与详情面板的方位可能不同，用户会困惑。
修复成本：小（统一用精确时刻）。

### P2-1　云属推断的确定性超出证据【源码已确认】

`clouds.ts:205-206` 只用了两个阈值（cover≥30 / rh≥80），却输出 11 种云属、
具体云底/云顶数值（`clouds.ts:262-263`）。云底是"层底 + 0.25×LCL"的经验式，
LCL 本身误差数百米。

**建议**：无法判定的层输出"云型不明"，而不是强行归类；云底/云顶标注"估算"。

修复成本：小（改文案与兜底分支）。

### P2-2　平滑会削掉短窗口【实测已确认】

`0.25/0.5/0.25` 权重的极端情况：单个小时 100 分、前后 0 分 → 平滑后 **50 分**。
真实火烧云窗口常常只有 20–30 分钟，正好被削平。
修复成本：小（保留原始逐时曲线，详情里双线显示）。

### P2-3　`canvasFactor` 已实现但未被使用【源码已确认】

`clouds.ts:363-382` 定义了"薄高云画布系数"，全仓库无调用点。
说明曾经想做"用云层剖面直接参与打分"，但没接线。
修复成本：小（接线即可，但**会改分数**，需要 A/B）。

### P3-1　`state.detail` 只对 `DETAIL_SPOT` 赋值【源码已确认】

`api.ts:640` 只在机位名等于常量时写 `state.detail`；
其余机位走 `row.detail`。前者基本已成死代码。
修复成本：极小（清理）。

### P3-2　`hourIndex` 的兜底分支是 O(n) 全表扫描【源码已确认】

`api.ts:29-33` 精确匹配失败时遍历所有时间戳并逐个 `new Date(...)`。
只在数据异常时触发，实际影响可忽略。
修复成本：极小。
