## 0. 一句话定位

**几何照明是一层独立、可解释、可复算的"解释器"**：
输入「观察者 + 太阳位置 + 云底/云边界（来自剖面/模式） + AOD」，输出
「几何上能不能被照到、从几点到几点、在天空哪个高度角、颜色偏什么、为什么可能翻车」。

它**不产生分数**，不改 `scoreOf()`，也不替代现有八层云层判据。
与现有系统的关系：现有评分回答"值不值得跑一趟"；几何引擎回答"如果真烧了，会以什么方式烧、什么时候烧"。

## 1. 模块划分（建议目录 `src/lib/litgeo/`）

| 模块 | 职责 | 依赖 |
|---|---|---|
| `earth.ts` | 地球曲率近似、视线↔高度换算、`√(2Rh)`、日落线速度查表/插值 | 无 |
| `sunlight.ts` | 给定太阳高度角与云底高度，算**光照区域的近/远边界**与光照半宽 | earth |
| `timing.ts` | 把边界距离换成"日落后 N 分钟"；算开始/结束/持续时间；含视野内延伸（5° 高度角） | sunlight + 线速度 |
| `aerosol.ts` | 气溶胶消光：`z_eff` 等效地表高度、等效云底、沿光路的光学厚度 | earth |
| `viewing.ts` | 观察者视线与云层交点的高度角、云边界可见性判定 | earth |
| `texture.ts` | 从剖面网格里取云底/云顶/云边界/云洞，生成几何引擎的输入 | `@/lib/xsec` 数据模型 |
| `attribution.ts` | 预报失败归因：按 [R0] §3.2 的三类不确定性打分/打标签 | 以上全部 |

**硬边界**：`litgeo` 不 import `@/lib/forecast/scoring`，只允许读 `sun.ts`、`xsec` 数据，
不允许写回 forecast 的 state 或缓存。

## 2. 数据模型（草案）

```ts
/** 一次几何计算的全部输入。所有长度单位 m / km 明确标注，避免混用 */
export interface LightGeoInput {
  observer: { lat: number; lon: number; altitudeM: number }
  /** 目标时刻（ms）与地点；太阳位置由现有 sun.ts 算，不重写 */
  timeMs: number
  /** 云底高度（m MSL）。来自剖面 / 探空 / 手填 */
  cloudBaseM: number
  /** 云顶高度（m MSL）。对流云模型要用 */
  cloudTopM?: number
  /** 云边界沿太阳方位的水平距离（km）。未知时用 undefined 并标记 uncertain */
  cloudEdgeKm?: number
  /** 视线/光路沿线 550nm AOD（无量纲）。可给单值或按距离的数组 */
  aod550?: number
  /** 气溶胶标高 H（km）。未知时按 0.5–4.0 做敏感性分析 */
  aerosolScaleHKm?: number
  /** 云洞模型用：云洞近/远边界距离（km） */
  gapKm?: { nearKm: number; farKm: number }
}

export interface LightGeoResult {
  sun: { el: number; az: number }
  /** 光照区域（相对观察者沿太阳方位的水平距离区间，km） */
  litRegionKm: { nearKm: number; farKm: number } | null
  /** 本地云底能否被直射阳光照到 */
  localCloudLit: boolean
  /** 云边界相对观察者的高度角（度，负 = 在地平线下） */
  cloudEdgeElevationDeg: number | null
  /** 火烧云在本地头顶的开始/结束/持续时间（ms / 分钟） */
  overhead: { startMs: number; endMs: number; durationMin: number } | null
  /** 含视野内（默认 5° 高度角以上）的总持续时间 */
  visible: { durationMin: number; extraMin: number } | null
  /** 气溶胶修正 */
  aerosol: {
    equivalentSurfaceKm: number
    effectiveCloudBaseKm: number
    /** 沿光路 550nm 光学厚度（无量纲，粗估） */
    pathOpticalDepth: number
    /** 阳光剩余强度比例（用于亮度分级） */
    transmittedFraction: number
  }
  /** 质量标记：哪些输入是缺失/估算的，页面必须显示 */
  quality: {
    cloudEdgeSource: 'profil' | 'manual' | 'missing'
    aodSource: 'open-meteo' | 'manual' | 'missing'
    scaleHAssumed: boolean
    /** 0–1，越大越可信；由输入完整度与不确定性来源决定 */
    confidence: number
    flags: string[]
  }
  /** 结构化解释（给页面直接渲染，不写死在模板里） */
  notes: Array<{ level: 'info' | 'warn'; text: string }>
}
```

## 3. 计算公式（标注出处与验证状态）

> 记号：R=6371 km，`h` 云底高度 km，`β` 太阳高度角（负 = 地平线下），`v_sun` 日落线速度 km/min。

### 3.1 地球曲率与视线（[R0] §1.1，正文明确）

```
h ≈ d·tan(α) + d²/(2R)            α = 视线高度角，d = 球面水平距离
α = 0 时  h = d²/(2R)  ⇒  d = √(2Rh)
```
正文称 1000 km / 100 km 高度内误差 < 2%。**可直接实现，并用 `√(2Rh)` 查表回归**（h=2→159.6 等）。

> **2026-11-01 已核实**：本节公式 F1–F8 已逐张核对原文图片，并用三个实战案例独立复现，
> 76 项数值检查全部通过。证据与推导见 `docs/阶段六-03litgeo-verify-验证报告.md`。

### 3.2 光照区域（[R0] §1.1 表 1.3 / 表 1.4）

```
高度 h 上被光照到的水平半宽 = √(2Rh)
全宽（"霞光深入距离"）= 2√(2Rh)
```
数值回归目标：h=2→319.23、3→390.95、6→552.78、8→638.21（误差 <0.1%）。
✅ **已核实**（image94）：`|l_f|max = 2√(2R·h_CB)`。原文"精确列"比它小 0.01–0.34 km（≤0.06%），
精确式未找到，但该差异对产品无影响（20 km/min 下约 0.015 min）。

### 3.3 时间换算

```
t_offset_min = Δx_km / v_sun
```
`v_sun` 取 [R0] §3.4 的查表（纬度 × 月）或由 `sun.ts` 的数值微分计算；
两者必须一致（验收：海南 11 月 ≈20.6 km/min）。

### 3.4 气溶胶消光（[R0] §1.1，**公式与表已互验，可直接实现**）

```
σ_a(z) = σ_a(0)·e^(−z/H)
AOD   = σ_a(0)·H
z_eff = H·ln(σ_a(0)/σ_th) = H·ln(AOD/(H·σ_th))      σ_th = 0.02 km⁻¹（原文取值）
等效云底 = 云底 − z_eff
```
回归目标（[R0] 表 4.1）：AOD=0.15、H=0.5/1.0/2.0/3.0 → 1.35/2.01/2.64/2.75 km（<0.03 km 误差）。

### 3.5 视线与云边界可见性（[R0] §1.2.4 + 案例）

云边界高度角 = `atan((h − 观察者海拔)/d) − d/(2R)`（曲率修正）；
验收用深圳案例：h=2000 m、d=200 km → **−0.32°**（原文值）。

### 3.6 待核实公式（**不进生产代码**）

- 火烧云三角近/远边界闭式解（W2）——先按几何第一性原理推导，再用 3 个案例数值对齐；
- 中云云洞最小长度条件（W3）；
- 卷云透过率经验判据（W4）。

> 处理方式：这几项写进 `candidates/` 式独立模块 + 单测，但**默认关闭**，
> 页面上只显示"该功能待核实"的占位说明。

## 6. 与 `/cross` 剖面联动（任务书第三节）

现状：`/cross` 横轴 0–50 km、5 个采样点、只到 12.5 km 高度。而火烧云几何要 50–500 km。

**方案（分两步，先只读）**：

1. **V1：叠加"光照区"图层到现有 50 km 剖面**
   - 给定太阳高度角，把"高度 h 上被光照到的水平半宽 √(2Rh)"画成剖面右上角的阴影区；
   - 只解释"这一小块剖面里，云底是否被照亮"，**不外推 200 km 外的云边界**；
   - 页面上写明"剖面只覆盖 50 km，边界距离需另行估计"。
2. **V2：独立的"光照几何图"（新画布，横轴 0–500 km，纵轴 0–20 km）**
   - 复用同一套 Canvas 组件（把 x 轴范围参数化），画：地表曲率、云层楔形、近/远边界、
     观察者视线、当前太阳高度光线族；
   - 云底/云顶用剖面同高度层的值外推（**外推要显式标注为外推**）。

不做的事：不改现有 50 km 剖面的语义，不把"几何可见"混进评分。

## 7. 预报失败归因（任务书第二节最后一条）

按 [R0] §3.2 的三类不确定性设计结构化字段（供未来反馈闭环）：

```ts
export type FailReason =
  | 'cloudAmountLow'      // 云量不足/云太薄
  | 'cloudEdgeMiss'       // 云边界位置偏差
  | 'cloudEdgeAngle'      // 云边界与太阳方位夹角过小
  | 'edgeWindFast'        // 云边界沿日落方向风速分量过大
  | 'blockedByOtherCloud' // 杂云/落幡/云砧遮挡
  | 'aerosolExtinction'   // 光路 AOD 或垂直分布估计错误
  | 'baseHeightWrong'     // 云底高度估计错误（落幡、多层）
  | 'localHaze'           // 本地低空霾影响观赏
  | 'modelBias'           // 模式本身偏差
  | 'unclassified'
```

规则先做成"可解释的启发式"（例如：AOD>0.5 且本地无霞 → `aerosolExtinction` 优先），
样本够了再谈统计校准。**没有样本前不写自动判定，只做人工选择 + 统计展示。**

## 9. 风险清单

1. **公式口径未核实**（W1–W4）→ 实现前必须核对，否则宁可不做。
2. **输入不足**：剖面只有 50 km，云边界常在几百 km 外；AOD 没有垂直分布。
   → 输出必须带 `confidence` 与 `flags`，页面要显示"哪些是估的"。
3. **概念越界**：几何可见 ≠ 会烧 ≠ 分数高。→ 三条信息在 UI 上必须分开写。
4. **维护成本**：多一套几何模块意味着多一套回归测试。→ 纯函数 + 案例固定，成本可控。
5. **与现有色阶冲突**：光谱颜色预测若与 `vividLabel` 并存，可能给出矛盾结论。
   → 颜色只做"参考倾向"，不覆盖现有业务色阶。
