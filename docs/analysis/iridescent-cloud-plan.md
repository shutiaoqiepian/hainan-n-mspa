## 一、彩虹逻辑现状：三段链路

「彩虹」在本站是**标量指数**，不是几何彩虹弧。它由三段组成：

| 段 | 函数 | 位置 | 做什么 |
|---|---|---|---|
| 几何窗口 | `rainbowHint()` | `scoring.ts:468` | 判断「日落前 0–2 小时内是否有像样降水 + 太阳 4–40°」→ 返回布尔 `rainNear` |
| 分数合成 | `rainbowOf()` | `scoring.ts:337` | 太阳角 3–42° × 降水 × CAPE 对流 × 云开缝 → 0–100 指数 |
| 渲染阈值 | `rainbowLabel()` + `Row.rainbow` | `scoring.ts:363`、`api.ts:1123` | `≥60 彩虹窗口 / ≥35 可能有虹 / ≥15 概率低 / 无` |

调用链：`api.ts` 主行循环里每个机位都算 `rainNear → rainbow → crep → pillar`（`api.ts:946–984`），结果写进 `Row.rainbowScore / rays / pillar`，再由 `DecisionHero.vue:125–131` 渲染成「四机会指数」（通透/云隙光/光柱/彩虹）。

## 二、彩虹逻辑的具体瓶颈与优化方向

1. **`rainbowHint` 每机位最多 3 次 `sunElevation()`（三角运算）**。全站 224 机位 ≈ 672 次重复计算，且与主 `sun` 位置（`sun.ts`）是两套独立计算。**优化**：把整天的逐小时太阳高度角预计算一次（或与主 sun 计算合并成一张表），`rainbowHint` 改为查表。收益：去掉 ~672 次三角运算 + 消除双源不一致。

2. **阈值三处抄写，有漂移风险**。`Row.rainbow = rainbow >= 35`（`api.ts:1123`）、词条 `c.rainbow >= 60/35`（`phenomena.ts:486`）、`rainbowLabel` `>=60/35/15`（`scoring.ts:363`）三处分写在三个文件，正是 AGENTS.md 反复警告的「抄数组」。**优化**：抽 `RAINBOW_TIER = { window:60, maybe:35, low:15 }` 常量，三处统一引用。

3. **窗口口径不一致**。`rainbowOf` 用 `el < 3 || el > 42` 硬门，`rainbowHint` 用 `4–40`。文献（SunsetBot #4）口径是「太阳 < 42°」。**优化**：统一为 42° 上界，3/4° 下界取一个（建议 3°），消除 `rainbowOf` 与 `rainbowHint` 各自为政。

4. **`matchPhenomena` 全量 `map→filter→sort` 无早退**。现有 68 条词条每个详情视图都全跑一遍再排序取前 5。**已被惰性求值缓解**（`api.ts:601` 注释确认只有「展开详情/生成名片」才算），不是热点；但新增词条时建议把 `match` 写成 O(1)–O(layers) 的短路判断，别引入重循环。

## 三、七彩祥云：形成机制与气象指标（文献）

### 3.1 机制：**衍射**，不是折射——这是与彩虹的本质区别

| | 彩虹 | 七彩祥云（虹彩云） |
|---|---|---|
| 机制 | 折射 + 反射 | **衍射** |
| 粒子 | 雨滴 ~1 mm（大而均匀） | 水滴/冰晶 **1–10 μm**（与可见光波长 0.4–0.7 μm 同量级） |
| 形态 | 规则弧形（42° 反日点） | 云边缘**不规则淡彩斑块**（粉/绿/青/蓝） |
| 观测方向 | **背对**太阳 | **面朝**太阳（太阳附近 10–40°，最多到 40°） |

来源：中国气象局官方科普（2017/2015）、IPB 大学气象系（衍射 + 1–10 μm + 单缝衍射原理）、Wikipedia「Cloud iridescence」+ Atmospheric Optics。

### 3.2 三个必要条件（中国气象局，多源一致）

1. **云与阳光角度 10°–40°**；
2. **含均匀小冰晶/水滴的薄云**——高积云（Ac）、卷积云（Cc）为主；
3. **天气晴朗、能见度好**（AOD 低、无雨）。

### 3.3 关键补充指标（文献）

- **云要薄、半透明**：光只穿过单颗粒子，所以**云边缘 / 半透明云 / 刚形成的云**虹彩最艳（新云水滴尺寸最均匀）。
- **水滴越小越绚烂**（在 1–10 μm 内）；太大（雨云）衍射不可见，太小（晴空）概率极低。
- **冷云甜区**：Ac/Cc 位于 5–10 km、温度 0 ~ −25 ℃（过冷水滴 / 冰晶）。太暖纯暖云水滴偏大，太冷纯卷云更多出「晕」而非「虹彩」。
- **雨后初晴加分**：降雨后新形成的薄云最均匀（中国气象局王秀荣）。

### 3.4 与三个易混淆天象的边界（别名去重）

- **日华（corona）**：虹彩的结构化形态——粒子非常均匀时，太阳周围出现亮盘 + 彩色环（<10° 是纯衍射，>10° 是第一级干涉）。站内目前**没有日华词条**，建议与七彩祥云合并说明或单列。
- **环地平弧（circumhorizontal arc）**：别名「火彩虹/彩虹云」，是**冰晶折射**、太阳 >58°，与七彩祥云（衍射、10–40°）完全不同。站内已有 `circumhorizon` 词条，别名重叠，需在文案里点明。
- **彩虹**：折射 + 反射、背向太阳、需雨。

### 3.5 可信度分级（按 research/README.md 口径）

| 结论 | 依据 | 等级 |
|---|---|---|
| 衍射机制、1–10 μm 粒子、单缝衍射 | 经典光学教材（Bohren & Huffman #12 已收录） | **A（原理）** |
| 三条件（10–40° / 薄 Ac·Cc / 晴朗） | 中国气象局官方科普 | **B** |
| 水滴 1–10 μm、越小越绚烂 | IPB 大学气象系专家、ABC+BOM | **C** |
| 面朝太阳、雨后初晴、边缘最艳 | 中国气象局 / CIRES / ABC+BOM | **B/C** |
| 具体阈值（云量 15–60%、AOD<0.3、pop<30…） | **无文献，本站需自定** | **D（需标定）** |

**结论**：机制有 A 级背书（衍射），判据有 B/C 级背书，但**具体阈值是 D 级**——和「天空霞」「雾」同属「环境符合度」，界面上**不许写「概率/准确率」**，只能叫「有机会」。

## 四、判定条件与触发规则（算法化）

### 4.1 主判据（D 级，需标定，先给初值）

| # | 判据 | 取值 | 数据来源 |
|---|---|---|---|
| P1 | 太阳高度角 | **10°–40°** | `PhenoContext.sunEl` |
| P2 | 面向太阳 | `faceOff === false` | `PhenoContext.faceOff` |
| P3 | 有薄 Ac/Cc | `layers` 中存在 `code ∈ {Ac,Cc}` 且 `cover 15–60` 且 `lit` | `PhenoContext.layers` |
| P4 | 空气干净 | `aod < 0.3`（或 `clarity ≥ 55`） | `aod` / `clarity` |
| P5 | 无雨 | `pop < 30` | `pop` |
| P6 | 冷云加分 | 该层 `t ≤ 0℃` | `layers[].t` |

### 4.2 分级（词条 `match` 返回 0/1/2）

- `2`（很有戏）：P1–P5 全满足 + P6（冷云）满足；
- `1`（有机会）：P1–P5 满足但无冷云佐证，或 `layers` 缺测退回中/高云量兜底（`mid∈15–60` 或 `high∈15–60`）；
- `0`：任一硬门不满足（角度、方向、云太厚/太薄、AOD 太脏、正在下雨）。

### 4.3 边界情况（需在实现与文案里处理）

| 边界 | 处理 |
|---|---|
| 太阳 <10°（日出日落） | 虹彩弱，且靠近太阳被眩光淹没——**判 0**，引导转拍霞 |
| 太阳 >40° | 衍射角超界，颜色消散——**判 0** |
| 云太厚（cover >60） | 光穿不过，无颜色——**判 0** |
| 云太薄（cover <15） | 无载体——**判 0** |
| AOD ≥ 0.3（霾） | 颜色被糊掉——**判 0** |
| 正在下雨（pop ≥ 30） | 不晴朗——**判 0**；但**雨后初晴**是加分（未来可加 `precipMm` 前序下降信号） |
| `layers` 缺测 | 退回中/高云量 15–60% 兜底，降为「有机会」且文案标「数据不足」 |
| 地面 RH 很高（雾） | 与 `fogbow`（雾虹）冲突，虹彩需云在 5–10 km 高空——由 P3 云属限制天然区分 |
| 与环地平弧别名重叠 | 文案明确「环地平弧要太阳 >58°、是冰晶折射；七彩祥云要 10–40°、是水滴衍射」 |

## 五、数据结构与参数配置调整

### 5.1 Phase 1（词条，低风险）——**无需新增数据结构**

`PhenoContext`（`phenomena.ts:23`）已有全部所需字段：`layers`（含 `code/genus/cover/rh/t/lit`）、`sunEl`、`aod`、`clarity`、`pop`、`faceOff`、`t2m`。新增词条只用它们，**零类型改动、零评分影响、不碰 `scoreOf`**，完全符合红线。

### 5.2 Phase 2（独立指数，可选，中风险）

若想让七彩祥云像彩虹一样出现在「四机会指数」里，才需要：

- `scoring.ts` 新增 `iridescenceOf(m, sun, layers, faceOff)` → 0–100（结构与 `pillarOf` 平行）；
- `scoring.ts` 新增 `iridescenceLabel(v)`；
- `types.ts` `Row` 加 `iridescence: number`；
- `api.ts` 主循环 + `SpotDetail` opts + `PhenoContext` 加 `iridescence`；
- `DecisionHero.vue` `opps` 数组加第 5 项「虹彩」。

### 5.3 参数配置表（D 级，新增）

```
虹彩判据：太阳角 10–40° / 云量 15–60% / AOD <0.3 / pop <30 / 云温 ≤0℃ / 面向太阳
```

### 与彩虹的整合关系

- **物理互补**：彩虹（背向太阳、折射、需雨）与七彩祥云（面向太阳、衍射、需晴）判据域几乎正交，`matchPhenomena` 里会**并列出现、互不冲突**——同一个机位可能同时「背对太阳有彩虹、面朝太阳有虹彩」。
- **判据复用**：两者共用 `sunEl`、`pop`，但方向相反（`faceOff` 一个取反），无需重复造轮子。
- **排序**：七彩祥云 `local:'少见'`（rarity=3）与彩虹同级，靠 `match` 分数 + 数组序决定谁在前。

### 建议落地顺序

1. **Phase 1**（词条 + 文案 + 文献登记）——低风险，可立即做；
2. **彩虹三项优化**（sun 表缓存 / 阈值抽常量 / 窗口统一）——独立小改，可与 Phase 1 分开提交；
3. **Phase 2**（独立指数进「四机会指数」）——中风险，需先确认产品上是否要「五机会指数」。
