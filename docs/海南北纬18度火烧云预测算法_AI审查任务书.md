9.  **保留人工摄影判断**：算法应帮助摄影师决定去哪、何时出发、朝什么方向拍摄，而不仅是预测一个抽象的天空分数。

## 3. 已发现、需要优先验证的疑点

以下是初步源码审查中发现的风险线索，不应未经验证就直接当作最终结论。请回到当前源码确认。

### 3.1 缺测值与真实恶劣天气可能混淆

在 `src/lib/forecast/scoring.ts` 的 `scoreOf()`
相关逻辑中，初步检查发现缺少部分气象字段时，会使用类似以下默认值：

-   高云量：90
-   中云量：60
-   低云量：70
-   降水概率：60
-   相对湿度：90
-   AOD：0.4（或代码指定的默认值）

如果当前代码仍如此处理，可能导致 API
缺测、变量未返回或数据解析失败时，系统生成看似正常但实际偏低的分数。反过来，默认值也可能造成不恰当的排序。

**请完成：** -
全面追踪每个输入字段的来源、单位、缺测标记、默认值和后续使用位置。 -
设计明确的数据质量状态，例如
`complete`、`partial`、`missing_critical`、`stale`、`api_error`。 -
区分"天气不利导致低分"和"证据不足导致低置信度"。 -
研究关键变量缺失时，是应停止评分、降级评分，还是给出区间；明确规则和依据。 -
在 UI 中显示数据更新时间、缺测变量、预报时效和置信度/数据完整度。 -
加测试覆盖 `0`、`null`、`undefined`、空字符串、NaN、API
错误和过期缓存等情况。

### 3.2 当前综合评分是启发式公式，尚不能证明准确性

初步检查到的 `scoreOf()`
逻辑包括高云、低云、中云、AOD、降水/湿度等因素的组合，并使用乘法结构、非线性幂次和分数上限。初步看到的函数名包括
`fHigh`、`fLow`、`fMid`、`fAod`、`fWet`。请以最新源码为准，完整复原所有公式和注释。

潜在风险： - 乘法组合会让单项因素主导整体分数。 -
各因素可能存在重复计权或相关性，例如云量、相对湿度、降水概率之间并非独立。 -
人工设定的阈值、底分、幂次和上限可能未经本地样本校准。 -
分数的数字范围不一定对应真实概率，也未必能跨季节、地点和预报时效比较。

**请完成：** - 解释每个函数、系数、阈值和指数的设计意图及证据来源。 -
检查公式的单调性、边界行为、极端输入和变量交互。 -
对阈值进行敏感性分析，识别哪些参数最影响最终排名。 - 至少提出 3
个可比较的模型版本： 1. 当前算法（Baseline，保持不变）； 2.
便于解释、容易回测的改进启发式模型； 3.
在有足够标注数据后可训练/校准的统计模型。 -
在无足够历史标注时，不要声称机器学习模型一定优于启发式模型。 -
对"评分""排序""概率"分别定义含义，不要混用。

### 3.3 Open-Meteo 网格与机位实际微气候存在空间误差

初步查看 `src/lib/forecast/api.ts` 时发现，代码可能会处理 Open-Meteo
返回的网格坐标、坐标吸附或多个机位复用同一个网格的问题。请重新确认实现。

海南沿海、丘陵、山地、水库和城市环境之间可能存在局地差异。机位坐标的天气数据不一定代表拍摄点附近真实天空；同一个预报网格内的多个机位也不应被误解为拥有独立的局地预报。

**请完成：** -
追踪请求坐标、返回坐标、网格吸附、机位绑定、缓存键和最终展示的完整链路。 -
检查经纬度精度、时区、海拔、地形和海陆差异处理。 -
为每个机位记录/展示预报网格位置、机位到网格的距离（若能可靠计算）、共享网格状态和局地代表性限制。 -
检查沿海海风、地形抬升、局地对流和云带移动等现象对预测的潜在影响。 -
不要对分辨率不足的数据做虚假的精细化插值，并宣称它代表真实局地天气。 -
如果可行，评估多个数值天气预报模式或高分辨率数据源的价值，但必须比较可用性、许可、更新时间、空间分辨率和历史回测表现。

### 3.4 云层分类是推断，不等于观测到的云种

初步查看 `src/lib/forecast/clouds.ts`
时发现，代码可能使用多个气压层的云量、相对湿度、温度、露点或位势高度来推断云层高度与云型。此类结果是基于模型场的算法推断，不是卫星或现场观测到的云种真值。

**请完成：** -
列出实际使用的变量、气压层、阈值、垂直高度换算和分类规则。 -
检查云量阈值、相对湿度阈值、云层高度划分与云型推断是否有可靠依据。 -
明确"模型云量""推断云层""推断云型""实际观测"四者区别。 -
对无法可靠判别的云型输出"不确定/无法判定"，不要强制分类。 -
分别评估高云对霞光着色的潜在贡献、低云对地平线遮挡的风险、中云对天空结构的影响；不要只将总云量视为唯一因素。 -
说明气压层数据的垂直分辨率、模式误差和时间采样对分类的限制。

### 3.5 评分必须服务于真实摄影决策

火烧云并不只是"云量越多越好"或"高云越多越好"。拍摄结果还受以下因素影响：

-   日出/日落时太阳是否能照亮云体；
-   云层高度、厚度、覆盖范围和分布方向；
-   太阳与机位、拍摄朝向之间的几何关系；
-   西/东地平线是否被低云、雨幕或地形遮挡；
-   云体与太阳之间的相对位置；
-   降水、雷暴、阵风和能见度等安全因素；
-   大气气溶胶、湿度、透明度和光学路径；
-   预报提前量与模式之间的分歧；
-   实际天空变化速度与数据更新时间。

请明确区分： 1.
**霞光/火烧云潜力**：天空出现可被日出/日落照亮云体的条件； 2.
**天空通透度/清晰度**：适合远景、银河或清晰层次的条件； 3.
**柱状光/丁达尔光等特殊光效**：需要独立判据，不应简单复用火烧云分数； 4.
**彩虹潜力**：需要降水、太阳方位/高度、观测方向和视线几何等条件； 5.
**安全性**：雷暴、强风、强降雨等风险必须独立展示，不得被高摄影评分抵消。

请检查当前 `scoring.ts` 中的
`clarityOf()`、`crepuscularOf()`、`pillarOf()`、`rainbowOf()`、`lclMeters()`
等函数（以实际源码为准），判断它们的物理含义是否清晰、输入变量是否充分、是否存在同一变量重复使用或概念混淆。

## 5. 必须建立的验证方案

算法优化的核心不是"公式看起来更科学"，而是能否预测真实拍摄结果。请设计可持续积累的数据闭环。

### 5.1 定义真实结果标签

设计一个低成本的人工标注表，让摄影师在日出/日落后记录： -
日期、机位、日出/日落时段； - 是否出现明显霞光； -
是否出现强烈火烧云； - 颜色、持续时间、覆盖范围和云层结构； -
天空是否被低云/雨幕遮挡； - 实际拍摄是否成功； -
可选：现场照片、拍摄方向、拍摄时间； - 标注者和标注置信度。

建议使用清晰的等级，例如： - 0：无明显霞光； - 1：轻微霞光； -
2：可辨识、值得拍摄； - 3：明显壮观； - 4：极强、具有代表性的火烧云。

请评估等级定义是否一致、是否需要示例图片或双人复核。不能把"摄影师没去拍"直接标成"没有火烧云"。

### 5.2 保存历史预报快照

每个预测样本尽量保留： - 机位 ID、坐标、网格坐标； -
预报生成时间与抓取时间； - 目标当地日期和日出/日落时间； -
预报提前量（例如 0--6 小时、6--24 小时、24--48 小时等）； -
各模式的云量、云层、湿度、降水、AOD 等原始输入； - API
返回的模型名称、版本和字段； - 基线评分、各子评分、算法版本； -
数据完整度、缓存新鲜度和错误状态； - 事后人工结果标签及其来源。

请检查当前缓存系统能否满足以上要求；如果不能，设计最小可行的日志/归档方案。不要只保存最终总分，因为这会使后续无法重算算法。

### 5.3 回测与指标

请根据标签类型选择指标，并说明为何适用：

-   有序等级标签：MAE、加权 Kappa、Spearman 秩相关；
-   二分类事件（如"是否达到值得出发级别"）：Precision、Recall、F1、PR-AUC；
-   概率输出：Brier score、可靠性图、校准曲线；
-   机位排序：Top-k 命中率、NDCG 或其他合理排序指标；
-   预报提前量：按不同 lead time 分层；
-   泛化能力：按季节、区域、海岸/内陆、地形和机位分层；
-   基线对照：当前算法与所有候选模型必须在同一测试集上比较。

避免数据泄漏：同一天、同一天气过程或相邻机位的样本可能高度相关；拆分训练集/测试集时，应考虑按日期/天气过程分组，而不是简单随机切分每条记录。

样本不足时，明确统计不确定性，不要将少量案例的提升夸大成稳定结论。

## 7. 推荐的改进架构（请评估，而非盲目照抄）

考虑将预测拆成几个相互独立的层，而不是用单一总分掩盖所有不确定性。

### 层 1：数据质量

输出： - `dataCompleteness` - `missingFields` - `forecastAge` -
`leadTimeHours` - `modelAgreement` - `gridDistanceKm`（若有可靠数据） -
`qualityStatus`

### 层 2：天气物理特征

分别提取： - 高云潜力； - 中云结构； - 低云/地平线遮挡风险； -
降水/雷暴风险； - 大气透明度相关指标； - 日出/日落太阳几何； -
机位朝向匹配； - 预报模式之间的差异。

每个特征都要给出输入来源、物理含义、取值范围、缺测处理和不确定性。

### 层 3：摄影目标评分

至少分别输出： - `gloryPotential` / 霞光潜力； - `skyClarity` /
天空通透度； - `specialLightPotential` /
特殊光效潜力（有足够依据时才启用）； - `rainbowPotential` /
彩虹潜力（必须满足相应几何与降水条件）； - `safetyRisk` / 安全风险。

### 层 4：校准与排序

-   先用透明、可解释的规则产生基础评分；
-   有足够历史标签后，测试统计校准或机器学习模型；
-   用回测指标决定是否替换基线；
-   单独报告数据不确定性，避免将它混入天气分数；
-   不因某个机位得分高而隐藏安全风险。

### 层 5：解释

为每个机位生成简明、可核验的解释，例如： - 加分因素； - 扣分因素； -
关键缺测项； - 预报模式是否一致； - 评分适用的预报时效； -
为什么该机位可能优于附近机位； - 哪些结论只是模型推断。

所有解释必须来自实际计算结果，不能由语言模型凭空编造天气原因。
