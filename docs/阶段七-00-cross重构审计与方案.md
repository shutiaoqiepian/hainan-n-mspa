## 1. 现状审计报告（P0）

### 1.1 渲染链路（旧版 v1）

```
data/cross/<spot>.json
  → expandPoints()                 // 每层展开成命名字段；null 保留
  → profileAt(si, h)               // 垂直：在相邻两个模式层之间按高度线性插值
  → cloudAt(d, h)                  // 水平：在相邻两个采样点之间按距离线性插值
  → alphaOf(q)                     // q(CLWMR+ICMR, mg/kg) 对数映射到透明度
  → cloudColor(liquidShare)        // 按液/冰比例混色
tooltip: nearestSample(d) + nearestLevel(h) → 直接显示该层原始值
```

### 1.2 逐像素审计结果（hk-xihai，t=2，az=265）

| 指标 | 数值 |
|---|---|
| 有色像素（alpha>0） | 13 067 / 48 400（27.0%） |
| 其中 tooltip 会显示「云水 0 / 云冰 0」的像素 | **4 073（占 31.2%）** |
| 其中颜色很强（alpha>0.15）的 | 1 912 |
| 错配像素对应的 tooltip 层 | 400 hPa ×1 985、200 hPa ×1 459、300 hPa ×629 |

**用户截图的现象被完整复现**：tooltip 取的是「最近模式层」的原始值（200 hPa → 云水 0 / 云冰 0 / 云分数 9%），
而像素颜色来自「沿高度插值的 q」——300 hPa 的 46 mg/kg 冰水向上抹到 200 hPa 附近，
在 12.4 km 处仍有 0.7 mg/kg，正好超过 0.5 mg/kg 的着色下限，于是出现「提示说 0、图上却是紫色」。

### 1.3 七个具体问题的结论

| # | 问题 | 结论 |
|---|---|---|
| 1 | 紫色色带用哪个变量 | **CLWMR+ICMR（总凝结水）的插值值**，与 TCDC 无关 |
| 2 | 云水/云冰是否阈值转换 | 无硬阈值；`alpha` 对数映射，**0.5 mg/kg 起色**，1 mg/kg 时 alpha≈0.064（肉眼可见） |
| 3 | 云分数是否参与云体绘制 | GFS 模式**不参与**；只有 Open-Meteo 兜底（无云水时）才用 cf 映射成伪 q |
| 4 | 不同变量是否不同插值 | 云水/云冰用同一套（垂直+水平线性）；等值线走规则网格；**tooltip 不插值** |
| 5 | tooltip 是否与图形同一数组 | **否**——图形用插值值，tooltip 用最近层原始值（这就是错配根源） |
| 6 | 缺测是否被当 0 | `totalCondensateMgKg` 只在**两者都缺**时返回 null；`(a ?? 0)+(b ?? 0)` 会把单侧缺测当 0；`liquidShare` 同样 |
| 7 | 颜色映射与图例是否一致 | **不一致/不充分**：图例只有色块，没有数值刻度、没有起色阈值、没说明液冰混色规则 |

补充量化：垂直层间距 0.68–2.74 km，tooltip 取「最近层」的最大偏差达 **±1.37 km**；
v1 的垂直线性插值会把单层云抹到上下各约 1–1.4 km。

### 1.4 已完成的修复（P0，已上线验证）

| 修复 | 实现 |
|---|---|
| tooltip 与图形同源 | 新增「光标处插值值」+「最近模式层原始值」两行，各自标语义；最近层用黄线标出位置与距离偏差 |
| 垂直不再抹 | 每层画成**以层中心为准的细带**（厚度 = min(1.1 km, 相邻层距×0.4)），并画出每层中心虚线；页面明示「每层是模式采样点，垂直分辨率有限」 |
| 四变量分离 | 新增视图切换：**综合（云水+云冰）/ 云水 / 云冰 / 总云量**；总云量只读 TCDC，绝不与凝结水混画 |
| 缺测不当 0 | 单侧缺测时按「可用者」着色但在 tooltip 标明；两侧都缺 → 不画；不再出现 `null→0` 的静默转换（页面上「缺测」字样保留） |
| 图例有数值 | 图内新增色标：`≥1 / 10 / 100 mg/kg`（总云量模式为 0/50/100%），与 `alpha` 映射同一套阈值 |
| 坐标语义 | 纵轴可切 **海拔 MSL / 离地 AGL**；右侧标注 9 个气压层；底部标真实格点位置 |

> 结论：**P0 的验收项 1/2/3（颜色与变量一致、提示与图形一致、四变量不混淆）已在 v2 满足**，
> 但仍需在 §7 的阶段 F 做全样本回归。

## 2. 数据变量映射表

| 变量 | JSON 字段 | 单位 | 来源 | 参与渲染 | 插值方式 | 图例 | 备注 |
|---|---|---|---|---|---|---|---|
| 云水 | `clwMgKg` | mg/kg（=10⁻⁶ kg/kg） | GFS CLWMR | 综合/云水模式 | 水平线性；垂直**不**平滑 | 青绿 | 模式微物理量 |
| 云冰 | `iciMgKg` | mg/kg | GFS ICMR | 综合/云冰模式 | 同上 | 紫 | 高空卷云主要成分 |
| 总云量 | `cfPct` | % | GFS TCDC | 总云量模式；综合模式不参与着色 | 同上 | 冷灰蓝 | **云分数 ≠ 水物质** |
| 温度 | `tC` | °C | GFS TMP | 等值线（可选） | 规则网格双线性 | 橙色等值线 | — |
| 相对湿度 | `rhPct` | % | GFS RH | 等值线（可选） | 同上 | 青色等值线 | 不是云量 |
| 风 | `uMs`/`vMs` | m/s | GFS UGRD/VGRD | 风矢量（可选） | 不插值（画在原层） | 绿箭头 | — |
| 垂直速度 | `wPaS` | Pa/s | GFS VVEL | 三角箭头（可选） | 不插值 | 蓝▲升/橙▼降 | 负=上升 |
| 位势高度 | `hgtM` | m (MSL) | GFS HGT | 纵轴坐标 | 逐格点逐层 | — | 不用压高表换算 |
| 地形 | `terrainM` | m | GFS orog | 地形轮廓 | 逐采样点 | 土黄 | **模式地形，不是 DEM** |
| 缺测 | `null` | — | — | 不着色 | — | 「缺测」 | 绝不写 0 |
| 地下层 | `belowGround=1` | 0/1 | 判据 `hgt ≤ terrain+5` | 地形遮罩 | — | 灰 | 不画云 |

## 3. 坐标与几何计算说明（P1）

| 量 | 定义 | 实现 | 误差/说明 |
|---|---|---|---|
| 横轴距离 | 从观察点沿方位角的大圆弧长，km | 5 个采样点，间隔 12.5 km，0–50 km | 与 GFS 格点求交后与真实格点位置一起标注（虚线） |
| 纵轴高度 | 海拔高度 MSL（可切 AGL=MSL − 机位地面） | 直接用逐格点逐层 `hgtM` | **不使用固定压高表**；GFS 位势高度本身有模式地形偏差 |
| 气压层 | 1000/925/850/700/600/500/400/300/200 hPa | 右侧刻度，画在各自真实高度 | 同一气压层在不同采样点高度不同（本剖面差 ≤ 数十 m），图上按观察点列标注 |
| 地形 | 每个采样点的 `terrainM` | 土黄填充；`belowGround` 层不参与着色 | 来源 GFS 0.25° orog（海南最高 616 m，真实五指山 1867 m） |
| 地球曲率 | 50 km 内下降 `d²/(2R)` = **0.196 km** | 本剖面横轴按弧长、纵轴按 MSL，**未**做曲率修正 | 50 km 内可忽略；扩展到 200–500 km 的光照几何必须加曲率（见 §6） |
| 观察者 | (0 km, 机位地面高度) | 图上三角标记 | 机位坐标来自 `spots.json` |
| 垂直分辨率 | 9 层，层间距 0.68–2.74 km | 每层细带 + 中心线 | **云厚无法优于 ~2.5 km**，页面必须写明 |

## 5. 云体渲染方案（P2）

1. **变量分离**：四个模式各自只读一个变量（见 §2），不允许综合模式在缺云水时偷偷用 TCDC 补。
2. **垂直不做跨层平滑**：每个模式层画成细带（≤1.1 km，= min(1.1, 相邻层距×0.4)），并画层中心线；
   因此「云顶/云底」只精确到**模式层中心 ± 半层距**，页面必须写成「受垂直分辨率限制」。
3. **水平线性插值**：5 个采样点之间线性插值，标注「格点之间为线性插值」；
   真实格点用虚线 + 底部 ↓ 标出，不伪造高频纹理。
4. **颜色与阈值**：log 刻度，`0.5 mg/kg` 起色、`1/10/100 mg/kg` 为图例刻度；总云量用线性 0–100%。
5. **液冰混色**：综合模式按 `clw/(clw+ici)` 在青绿↔紫之间混；tooltip 同时给原始两值与液占比。
6. **缺测**：不着色；tooltip 写「缺测」；两侧缺测不插值出颜色。
7. **云层信息卡**：列出每个连续有云层的 层中心高度、气压、液/冰、峰值，并给出「厚度 ≥ 层间距」的说明。

## 6. 太阳光路计算方案（P3，复用已核实的几何）

- 太阳位置：现有 `src/lib/forecast/sun.ts` 的 `sunPosition()`（不重写）。
- 平面投影：`s‖ = cos(el)·cos(az − φ)`、`s⊥ = cos(el)·sin(az − φ)`、平面内视高度角 `atan2(sin el, s‖)`；
  `φ` = 剖面方位。太阳在背后（s‖<0）或偏离 >25° 时降低不透明度并提示。
- **几何照明判定**（已用三个案例验证，见 `docs/阶段六-03`）：
  - 光照最大深入距离 `2√(2R·h_CB)`；观察者距云边界 d ≤ 该值才可能被照亮；
  - 本地云底被照亮时间窗：`[d/(2v), √(2R·h_CB)/v]`（v = 日落线速度，查表 20–21 km/min）；
  - 云边界视角高度角：`atan(h/d) − d/(2R)`。
- **明确区分**：图上光线只是几何投影；**几何相交 ≠ 明亮火烧云**（还取决于云量、厚度、气溶胶消光、观测方向）。
  页面上固定文案：「本图展示太阳几何关系与模式云场，未进行辐射传输计算」。
- 下一步（阶段 D）：把上述照明判定做成「太阳几何卡」的四个数字：能否照到、开始/结束时间、边界高度角、方位差。

### 7.1 全国 224 架构（任务书《范围修正》§1–§5）

- **通用适配层**：`spots.json`（224 条）+ 新 `spots-meta`（海拔、主方位、是否观测点）；
  机位 id 全国统一 `<prov>-<slug>`，文件名不再写死 `hn-`。
- **统一引擎**：一个 `build_cross.py` 支持任意机位列表；按 **1° tile 分组下载**（同一 tile 内的机位共用一次 GFS 取数），
  单机位 5 方位 50 km 需要 ≤0.41°lat × 0.52°lon 窗口（实测最大），一个 1°×1° tile 可覆盖多个机位。
- **地形适配**：GFS orog 为模式地形（0.25°，平滑严重）。真实 DEM 未接入前，
  页面必须显示「地形来源：GFS orog 0.25°（≈28 km 平滑），非高分辨率 DEM」。
- **海拔缺失**：224 个机位**全部没有海拔字段**。方案：用 Open-Meteo elevation（Copernicus DEM GLO-30）
  批量补齐并标注来源与精度（±10 m 级），无法补齐的机位明确标记 `elevation: null` 并拒绝生成剖面。
- **批量成本**（实测基准：8 机位 × 20 sections = 341 KB；filter 每时次 41.8 KB / 2.8 s）：

| 方案 | sections/机位 | 数据量 | 下载请求 | 生成时间（估） |
|---|---|---|---|---|
| 全量 4 时次 × 5 方位 | 20 | ≈9.3 MB | ≈896 次 | ≈45 min（串行） |
| 建议首版：**3 时次 × 1 方位**（按当天日落方位） | 3 | **≈1.4 MB** | ≈224 tile 组 ≈ 150–300 次 | ≈8–15 min |
| 试点 8 机位保留 4×5 | 20 | 341 KB | 32 次 | 15 s |

> 结论：**全国首版按「每机位 3 时次 × 1 方位」生成**，试点 8 机位保留 4×5 可旋转；
> 更新频率先 1 次/天（全国日落跨 17:00–20:30，单轮即可覆盖），实测 git 增长后再决定是否加密。
> CI 用 `concurrency` + 失败重试 + 质量报告，单机位失败只跳过该机位并记录原因，不整体失败。
